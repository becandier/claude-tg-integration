# Claude Code + Codex Telegram Integration

Двусторонний мост между Telegram, Claude Code и Codex CLI через tmux-сессии. Управляй обоими coding-агентами с телефона: запускай проекты, отправляй задачи, файлы и голосовые сообщения, переключай модели и reasoning effort.

## Возможности

- **Forum Topics** — каждая сессия в отдельном топике, удобная навигация между проектами
- **Названия по смыслу разговора** — Claude/Codex выбирает короткое название, и тема становится `🚀 gpt-5.6-sol · projects · Рефакторинг tg-integration`; в префиксе стоит модель сессии, а не тип агента
- **Два агента** — Claude Code по умолчанию и Codex CLI по команде `/newstart codex`
- **Мульти-сессии** — несколько Claude/Codex-сессий параллельно, каждая в своём tmux pane
- **Медиа** — фото, видео, GIF, видеокружки, аудио и документы; агент получает путь к скачанному файлу (лимит Bot API на приём — 20 МБ)
- **Файлы от агента** — файл до 50 МБ можно прислать в топик через `tg_send_file.sh`
- **Голосовой ввод** — голосовые сообщения распознаются офлайн через Whisper
- **Permission prompts Claude** — инлайн-кнопки ✅/❌ для подтверждений Claude
- **Навигация по проектам** — drill-down браузер с инлайн-кнопками
- **Мониторинг активности** — уведомления, если Claude или Codex работает долго или завис
- **Ход работы Codex** — промежуточные сообщения Codex приходят в топик во время длинного задания; ⚡ означает передачу в tmux, 👀 — приём ввода Codex
- **Статистика сессии** — `/stats` показывает занятый контекст и израсходованные лимиты плана по каждому окну, включая отдельно считаемые модели
- **Форматирование** — Markdown → HTML: код, таблицы, bold/italic
- **Терминал** — автоматически открывает iTerm2/Terminal.app с tmux attach
- **Готовность и модель** — стартовое сообщение обновляется после появления строки ввода и показывает текущую модель Claude/Codex
- **Обновление Codex из Telegram** — варианты стартового update-диалога выводятся кнопками; после обновления CLI перезапускается в том же pane
- **Очередь сообщений** — во время запуска или блокирующего меню текст и ссылки на скачанные файлы сохраняются в session storage; очередь переживает перезапуск watcher и отправляется по порядку после готовности CLI

Если CLI показывает неизвестный стартовый диалог, бот присылает его текст и ждёт решения в терминале. Сообщения в это время остаются в очереди. Неудачное обновление запускает установленную версию Codex; если и её не удалось запустить, бот сообщает об ошибке и сохраняет очередь. Хранилище сессий находится в `/tmp/claude_tg_sessions.json`: очистка `/tmp` или закрытие сессии удаляет её очередь.

Если доставку сообщения блокирует диалог Codex `Approaching rate limits`, мост выбирает `Keep current model` и ждёт возвращения строки ввода перед отправкой очереди. Модель и effort сохраняются, напоминания о лимитах глобально не отключаются. Распознанный текст голосового хранится в той же очереди: реакция ✍️ может оставаться до его доставки. Это обработка конкретного диалога CLI 0.157.0; неизвестные диалоги и исчерпание квоты автоматически не подтверждаются.

`/model` показывает текущую модель вместе с effort и кнопками для его изменения. После выбора модели или effort оба значения остаются видны; при старте чата effort также выводится в уведомлении. Для Codex значение читается из текущей строки состояния CLI. Например, для `gpt-5.6-sol · medium` выбери Sol в `/model`, затем нажми Medium (или отправь `/effort medium`).

Для Claude Code выбор действует только на сессию: мост открывает пикер `/model`, подводит курсор к строке модели и жмёт `s` («use this session only»), не трогая default для новых сессий. Если CLI спрашивает «Switch model?» (история закэширована под текущую модель), мост подтверждает смену. Имя, которого в пикере нет (полный идентификатор), уходит командой `/model <имя>` — Claude Code 2.1.29x сохраняет его ещё и как default. Успех подтверждается строкой `Set model to …` в транскрипте; без неё мост сообщает об ошибке и не меняет сохранённую модель. Списки в `/model`, `/stats` и кнопках effort показывают сохранённый выбор, а не приветственную шапку CLI, которая после смены модели устаревает.

`/model` Codex умеет продолжить уже открытое меню и подтверждает смену по текущей строке состояния CLI. Во время выполнения задачи команду нужно повторить после завершения ответа. Если сохранённый effort не поддерживается выбранной моделью, используется выделенный CLI вариант.

## Как работает

```
Telegram (Forum Topic) ──→ tg_reply_watcher.py ──tmux paste-buffer / send-keys──→ Claude/Codex
Telegram (Forum Topic) ←── tg_stop_hook.sh ←───── Claude Stop hook
Telegram (Forum Topic) ←── tg_notify_hook.sh ←─── Claude Notification hook
Telegram (Forum Topic) ←── tg_stop_hook.sh ←──────── Codex Stop hook
Telegram (Forum Topic) ←── tg_reply_watcher.py ←──── Codex commentary в локальном журнале
Telegram (Forum Topic) ←── tg_codex_submit_hook.py ← Codex UserPromptSubmit hook (👀)
```

Текст попадает в CLI одним bracketed paste (`tmux paste-buffer -p`). Посимвольный набор `send-keys -l` Claude Code получает только для короткой однострочной реплики (до 120 символов): длинный набранный текст он теряет с начала.

Каждая сессия живёт в отдельном Forum Topic — навигация между проектами в один тап.

Мост помечает входящие сообщения префиксом `[TG | ~/.claude/tg-integration]`, по которому агент применяет скилл `tg-chat`. Скилл велит выбрать название темы через `python3 ~/.claude/tg-integration/tg_topic_title.py 'Название темы'`. Команда использует текущий `TMUX_PANE` и сохраняет запрос локально. Watcher применяет его через `editForumTopic` обычно в течение 30 секунд, повторяет неудачные запросы и не отправляет уже применённое имя повторно. Название формирует сам агент по контексту, отдельный вызов модели не нужен.

Префикс — это модель сессии и проект: `🚀 Opus 5 · rocket · Переезд бота на Postgres`. Модель берётся из `/model`-состояния сессии, парентезис вроде `(1M context)` отбрасывается, алиас приводится к виду CLI (`opus` → `Opus`). Пока CLI не запустился и модель неизвестна, в префиксе стоит тип агента; watcher заменит его сам. Смена модели через `/model` переименовывает топик. Пустые части префикса опускаются вместе с разделителем; лимит Telegram — 128 символов.

## Установка

### 1. Создать Telegram-бота

Через [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен.

Настройки бота (Bot Settings):
- **Group Privacy** → **Turn OFF** (бот должен видеть все сообщения в группе)
- **Allow Groups** → ON

### 2. Создать супергруппу с Forum Topics

1. Создать группу в Telegram (любое название, например "Claude Code")
2. Настройки группы → Topics → включить
3. Добавить бота в группу
4. Сделать бота администратором с правом **Manage Topics**
5. Узнать ID группы (переслать сообщение из группы в `@userinfobot`)

### 3. Конфигурация

```bash
cp tg_config.sh.example tg_config.sh
```

Заполнить `tg_config.sh`:

```bash
TG_BOT_TOKEN="your_bot_token"
TG_CHAT_ID="-1001234567890"       # ID супергруппы (отрицательное число)
TG_USER_ID="your_user_id"         # узнать: @userinfobot
TERMINAL_MODE="tab"               # "tab", "window" или "none"
TERMINAL_APP="iterm"              # "iterm" или "terminal"
```

### 4. Зависимости

```bash
brew install tmux ffmpeg

# Для голосовых сообщений (опционально)
brew install whisper-cpp
mkdir -p whisper-models
# Скачать модель: https://huggingface.co/ggerganov/whisper.cpp/tree/main
```

Установи и авторизуй нужные CLI:

```bash
claude --version
codex --version
```

Codex-сессии запускаются с `--dangerously-bypass-approvals-and-sandbox` и `--dangerously-bypass-hook-trust`. Это режим полного локального доступа без Telegram approval-кнопок. Используй его только на доверенной машине и в доверенных проектах.

Codex использует `UserPromptSubmit` и `Stop` hooks из `~/.codex/hooks.json`. Первый привязывает Telegram-ход к локальному журналу; watcher ставит 👀 после появления сообщения пользователя в журнале Codex и пересылает новые сообщения `commentary` с задержкой обычно до 2 секунд. Для уже запущенных CLI-сессий watcher находит открытый журнал по tmux pane. `Stop` передаёт итоговый `last_assistant_message` в общий Telegram formatter. Защита по `turn_id` не позволяет старому `notify` и native hook отправить итог дважды во время переходного периода. Сигнал 👀 подтверждает приём ввода CLI, но не доказывает, что модель уже учла каждую деталь сообщения. Формат локального журнала Codex не является стабильным API, поэтому после обновления CLI пересылку промежуточных сообщений нужно перепроверить.

Добавь обработчики в `~/.codex/hooks.json`, сохранив другие существующие hooks:

```json
{
  "hooks": {
    "UserPromptSubmit": [{"hooks": [{"type": "command", "command": "python3 ~/.claude/tg-integration/tg_codex_submit_hook.py", "timeout": 5}]}],
    "Stop": [{"hooks": [{"type": "command", "command": "bash ~/.claude/tg-integration/tg_stop_hook.sh"}]}]
  }
}
```

### 5. Хуки Claude Code

В `~/.claude/settings.json` добавить:

```json
{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "bash ~/.claude/tg-integration/tg_notify_hook.sh"
          }
        ]
      }
    ],
    "Stop": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "bash ~/.claude/tg-integration/tg_stop_hook.sh"
          }
        ]
      }
    ]
  }
}
```

### 6. Запуск

```bash
python3 -u ~/.claude/tg-integration/tg_reply_watcher.py
```

Или через LaunchAgent для автозапуска — см. `start_watcher.sh`.

## Команды бота

В меню бота выведены только частые команды. Остальные работают, если набрать их вручную — они намеренно убраны из списка, чтобы он не разрастался.

| Команда | В меню | Описание |
|---------|--------|----------|
| `/newcodex [проект]` | да | Запустить Codex; без проекта открывает picker |
| `/newclaude [проект]` | да | Запустить Claude Code; без проекта открывает picker |
| `/effort [уровень]` | да | Reasoning effort активного агента; список зависит от Claude/Codex |
| `/model [алиас]` | да | Модель активного агента; список читается из живого `/model` picker, для Claude смена только для сессии (`s`) |
| `/stats` (`/usage`) | да | Контекст окна и лимиты плана для сессии текущего топика |
| `/close` | да, последней | Закрыть сессию (в топике — закрывает сессию и удаляет топик) |
| `/newstart [codex] [проект]` | нет | Полная форма запуска сессии; `/newcodex` и `/newclaude` её заменяют |
| `/projects` | нет | Выбрать проект из ~/projects |
| `/sessions` | нет | Список активных сессий |
| `/cleanup` | нет | Очистить все скачанные медиафайлы |

## Статистика сессии

`/stats` (синоним `/usage`) отвечает в топике одним сообщением: сколько занято контекста и на сколько израсходованы лимиты плана по каждому окну — включая модели, которые считаются отдельно (например, `Неделя · Fable` у Claude или Spark-лимиты у Codex).

Данные снимаются с того же TUI, что видит человек в терминале:

- Claude Code — `/context` для контекста и `/usage` для лимитов; оверлей прокручивается, потому что в узком окне блоки лимитов не влезают в один кадр, и закрывается Escape
- Codex — одного `/status` достаточно: там и модель с планом, и контекст, и все лимиты

Команда работает только в простое: обе CLI принимают слэш-команды между ходами. Если агент занят или экран не прочитался, бот отвечает тем, что доступно из файлов, и помечает это:

- контекст Claude — точные токены последнего запроса из транскрипта сессии (`≈` в сообщении)
- контекст и лимиты Codex — снимок события `token_count` из rollout-журнала сессии

Размер окна контекста Claude не угадывается: у одной модели бывает и 200k, и 1M. Если ни `/context`, ни шапка CLI его не показали, бот печатает количество токенов и прямо пишет, что окно не определено.

## Использование

1. Отправь `/newstart my-project` для Claude или `/newstart codex my-project` для Codex
2. Без имени проекта бот покажет project picker и сохранит выбранный тип агента
3. Бот создаст **Forum Topic** и запустит агента в tmux
4. Пиши прямо в топике — текст автоматически уходит в нужную сессию (reply не нужен)
5. Отправляй фото, видео и документы — агент получит путь к файлу
6. Кнопки ✅/❌ появляются только для permission prompts Claude; Codex работает в Full Access
7. Короткие ответы (`да`, `y`, `ok`) подтверждают только permission prompts Claude
8. Если агент работает дольше 2 минут — придёт уведомление "⏳ всё ещё работает"
9. `/close` в топике — закрывает сессию и удаляет топик

Голосовые сообщения распознаются и отправляются как текст.
Медиафайлы хранятся в `/tmp/claude_tg_media/` и автоматически удаляются при закрытии сессии.
Приём ограничен 20 МБ — это лимит `getFile` в Bot API, обойти его можно только локальным Bot API server.
Если файл больше, мост ставит 👎 и пишет в топик, что именно не принял.
Реакции на сообщения ограничены набором Telegram: ⚡ — передано в сессию, 👀 — Codex принял ввод, ✍️ — голосовое распознаётся, 👎 — файл не принят. Эмодзи вне набора отклоняется с `REACTION_INVALID`, и мост заменяет его на ⚡. Bot API допускает одну реакцию бота на сообщение, поэтому 👀 заменяет ⚡.

## Отправка файлов из сессии

Claude, Codex или ты вручную можете отправить файл в Telegram:

```bash
~/.claude/tg-integration/tg_send_file.sh <файл> [подпись]
```

- Файл уходит как документ (`sendDocument`), без сжатия, лимит Bot API — 50 МБ
- Внутри tmux-сессии файл попадает в топик текущей сессии, иначе — в General
- Подпись обрезается до 1024 символов (лимит Telegram)
